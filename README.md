## 🚀 新規セッション開始時の推奨手順

### Step 1: 全体像の把握（必読・この順序）
1. **本ファイル** — プロジェクト全体像と現状
2. **[AGENT.md](AGENT.md)** — 行動規範・採用ワークフロー・禁止事項。特に **§7（2セッション並行運用ルール）** を必ず読む
3. **[activity_log.md](activity_log.md)** — 他セッションの直近活動を把握（最低直近10-20エントリ）
4. **セッション識別子を決め、`activity_log.md` に `[SESSION-START]` を記録**
5. **[tasks.md](tasks.md)** — タスク管理台帳（進行中・未着手タスクの把握）
6. **[questions.md](questions.md)** — ユーザー回答済みの事項と未回答の事項を確認
7. **[notes_input.md](notes_input.md)** — インプット資料の詳細要約（元ファイル再読込は不要）
8. **[design_rules.md](design_rules.md)** — 確定済みデザイン要素（厳守対象）

### Step 2: 現状確認
- `questions.md` を見て、**ユーザー回答が追加されているか**をチェック
- 新規回答があれば、該当内容を `design_rules.md` / `notes_input.md` に反映し、`tasks.md` の関連タスクを完了に
- `tasks.md` の進行中タスクの状態を確認
- モックアップディレクトリ (`mockup/`) の有無を確認

### Step 3: 作業再開
- **セッション冒頭**: 未着手タスクと未回答質問の要約をユーザーに提示
- 未回答の必須質問（🔴）があれば、まずユーザーに回答を促す
- 回答済みの事項があれば、デザイン壁打ち（HTMLモックアップ作成）に着手
- HTMLモックアップ生成時は **`frontend-design` スキルを必ず起動**
- 作業中に新しく確定した要素は即座に `design_rules.md` に追記
- 新規に作業項目が発生したら `tasks.md` に起票
- 応答の末尾で、残タスク・未回答質問があれば簡潔に再提示

## 📨 ユーザーとの対話運用

### Agentの振る舞い（重要）
- **セッション開始時**: `tasks.md` と `questions.md` を読み、残タスク・未回答項目をユーザーに提示
- **セッション内で回答があれば**: Agentが自動で `questions.md` を更新し、関連ファイル（`design_rules.md` 等）にも反映。対応する `tasks.md` のタスクステータスも更新
- **新規タスク発生時**: 都度 `tasks.md` に起票
- **作業の節目**: 完了タスクと次タスクを示しつつ、未解消の残件を提示
- **応答末尾**: 未解消の🔴必須項目があれば簡潔に再提示（残量多い場合は絞って）
- **新規の不明点**: 壁打ちや検討の過程で出てきたら `questions.md` に追記

### ユーザーの振る舞い
- `questions.md` の回答欄に直接記入してもOK
- セッション内で口頭（対話）で回答するだけでもOK（Agentが反映する）
- 残タスクの進捗確認・優先度変更の指示はいつでも可

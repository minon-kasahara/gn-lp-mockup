## ch-g0 — 0. レスポンシブ・モバイル前提（最重要） （判定:一部詰まる / blocker:2）
> 本章は実操作より方針・写像表が中心の「方針章」で、§0.4 の変換表と基本4ステップは初心者に親切に書けている。ただし「今やる実操作」である §0.2 のブレークポイント設定手順に、Studio のどのパネル/メニューでスモールを「有効化」「追加」するのか、数値入力欄がどこにあるのかの具体が無く、初心者が最初の一歩で詰まる（blocker）。また §0.2 表と §0.3 図で「Tablet(1024)」「Tablet 構造リフロー」と本文・訂正と矛盾する古い記述が残っており、どれが正か初心者には判断不能（blocker）。その他、原物CSS値を初心者が自力で確定する前提・clamp/order/keep-all 等の未落とし込み・「公開」ボタンや Reset override の場所未指定など、minor〜major が複数。本章の操作量自体は少ないので、設定手順と矛盾図さえ直せば再現可に近づく。
- **[blocker]** 0.2 §g0-2 【操作】ブレークポイント有効状態の設定 ステップ2「スモールを有効化（ツールバーの「＋」または「スモール」を選択）→数値入力欄に 1024 を入力」
  - 問題: Studio初心者が最初に行う唯一の実操作なのに、スモールを有効化するUIが特定できない。「ツールバーの＋」か「スモール」のどちらが正か曖昧で（or表記）、画面下部ツールバーのどこに＋があるのか、押すと何が出るのか（メニュー/リスト/ポップオーバー）、「数値入力欄」がそのどこに現れるのかが書かれていない。ステップ1で確認するデバイス幅切替には初期状態で Small が無い前提なのに、追加の導線が不明。ここで止まると以降の全章の前提（4段BP）が組めない。
  - 修正: 「画面下部ツールバーのデバイス幅アイコン群の右にある＋（ブレークポイント追加）をクリック→一覧から『スモール』を選ぶ→ツールバー中央に出る幅の数値入力欄に1024と打ちEnter」のように、クリック対象・出てくるUI・入力欄の位置を1操作ずつ図入りで分解する。
- **[blocker]** 0.3 §g0-3 写像図の右カラム（SVG内テキスト）「Tablet（1024）」「1024 構造リフロー＋768 余白」、および figcaption「1024 は構造リフローのため Tablet に」
  - 問題: 本文・§0.2訂正callout・写像表はいずれも「1024 の構造リフローは Small(1024) に置く／タブレットは上限990で1024不可」と明記しているのに、直前の図と図キャプションだけが旧版の「Tablet（1024）に1024構造リフロー」のまま残っている。初心者は本文と図のどちらが正しいか判断できず、誤って Tablet に1024リフローを置く（=そもそも990上限で設定不能）。同章内の自己矛盾は最も危険。
  - 修正: 図の右カラムを「Small（1024）／1024構造リフロー」「Tablet（840）／768 余白調整」に修正し、figcaption も「1024 は Small に、768 は Tablet に」へ統一して本文と一致させる。
- **[major]** 0.4 実装前（着手前チェック）ステップ1「対象セクションの原物 PC 値（幅・gap・padding・色・フォント・z-index）を原物 CSS から確定する」
  - 問題: Studioしか触れない初心者にとって「原物CSSから値を確定する」はCSSを自力で読む作業で、§0.4変換表（CSS→Studio操作）の射程外。原物HTMLの該当行をどう開きどの行を見ればよいか、行番号(L740等)はどのファイルのものかの導線が無い。実際には各§5-x章で具体値が与えられる設計のはずだが、本ステップだけ読むと初心者は原物CSS解読を強いられたと誤解して止まる。
  - 修正: 「原物PC値は各§5-x章の手順に転記済みなので、その章の指定値を使う。原物CSSを自分で読む必要はない（行番号は出典確認用）」と明記し、CSS解読を初心者の作業から外す。
- **[major]** 0.4 実装中 ステップ2「hero-title は テキストタブで PC の nowrap を解除しサイズ縮小（clamp 相当）」
  - 問題: 「clamp 相当」「サイズ縮小」が具体値で無い（基準(d)曖昧値）。clampは§0.4変換表にもStudio操作として載っておらず、初心者はテキストタブのサイズ欄に何px入れればよいか分からない。写像表ではclamp(32px,5.4vw,52px)と原物値はあるが、Studioのサイズ欄に単一値を入れるのか可変指定があるのかの操作落とし込みが無い。
  - 修正: 「テキストタブ→サイズ を 例:36px の固定値に下げる（Studioのvw可変は§xで扱う/当面は固定px）」のように、入れる具体数値と単位を明示する。
- **[major]** 0.4 実装中 ステップ3「Hero グリッドを order 制御で縦1カラム」「ヘッダー高さ縮小」
  - 問題: order（並べ替え）はCSS用語で、§0.4変換表に対応操作が無い(基準b)。Studioで子の並び順をどこで変えるか（レイヤーの上下入替か専用プロパティか）未記載。「ヘッダー高さ縮小」も縮小後の値が無い(基準d)。初心者はMobileでHeroの内部要素をどう積み替えるか操作不能。
  - 修正: 「Mobileでは Hero/Left と Hero/StatPanel の並びをレイヤーパネルでドラッグして入替え、親の方向＝縦にする」等、order をStudioのレイヤー並べ替え操作に翻訳し、ヘッダー高さの目標値も記す。
- **[minor]** 0.3 §g0-3 改行クラスのcallout「該当語句を1つの Text 要素 or 文節をスペース無しでまとめる」「PC 用 Text と Mobile 用 Text を別レイヤーで2つ用意し、BP 別の表示/非表示（レイヤーパネルの目アイコン）で出し分ける」
  - 問題: 方針は読めるが操作が半分しか落ちていない。word-break:keep-all（文節改行）をStudioのどこで設定するかは§0.4変換表に項目が無い(基準b)。また要素2重化は『目アイコンで非表示』までは書いてあるが、BP別に表示/非表示を切り替える具体手順（Mobileを選んだ状態でPC用Textの目を消す等）の順序が抜けており、初心者はBP別出し分けの操作順で迷う(基準e)。
  - 修正: keep-allの設定場所を変換表に追加し、要素2重化は「下部ツールバーでMobileを選択→レイヤーでPC用Textの目アイコンを消す／Defaultに戻すと再表示」と操作順を明記する。
- **[minor]** 0.4 実装後 ステップ1「エディタ右上の『公開』でステージング URL に反映」/ 実装中 ステップ4「プロパティ横の『Reset override（上書きリセット）』矢印」
  - 問題: 『公開』ボタンの位置は『右上』と一応あるが、押下後にステージングURLがどこに表示/取得されるか不明(基準a)。Reset overrideも『プロパティ横の矢印』とあるが、上書き時に枠が色付くプロパティの具体的にどこに矢印が出るか初心者には見つけにくい。いずれも致命的ではないが手が止まりうる。
  - 修正: 公開後のURL確認場所（公開完了ダイアログ/プロジェクト設定のドメイン欄）と、Reset overrideアイコンの見た目（色付き項目名にホバーで現れる戻し矢印）を一文添える。
- **[minor]** 0.2 表 Small行「基準幅 1024px（有効化して設定。1024 不可なら既定 1140 でも可）」/ ステップ2「1024 が入らない環境では既定 1140 のままでも可」
  - 問題: 1024が入る環境と入らない環境の判定基準が示されず、初心者は自分がどちらか分からないまま1024と1140のどちらを採るか決められない(基準d)。後続章は『Small(1024)』前提で書かれているため、1140にした場合に各章値をどう読み替えるかも不明。
  - 修正: 「数値欄に1024と入れてEnter後、値が1024で確定すればOK／弾かれて戻る環境のみ1140を使う。1140にした場合も各章のSmall指定値はそのまま使う」と判定法と読み替えを明記する。

## ch-g1 — 1. Studioプロジェクト初期設定 （判定:一部詰まる / blocker:0）
> 本章は「メタ/基準幅/フォント/Base骨格」の4本柱を確定する方針章で、概念整理・実値の引き渡しは非常に丁寧。アクセス経路（グレー余白クリック→ページ設定パネル、[サイト]/[ページ]タブ）やフォント追加の入口（右パネル→[テキスト]タブ→Typography→Font→Add Font→Google Fonts）など、初心者が最も迷う「どこを開くか」が明示されている点は優秀。重大ブロッカーは無く、§0.4変換表＋本文で大筋は再現できる。ただし「実際にクリックする粒度」に落ちていない箇所が散在し、初心者が手を止める典型（1ステップ多操作の未分解・どこをクリックするか曖昧・Studio固有UIの位置不明）が複数ある。特にFont Listの「並べ替え」「ラベル設定」「サイト言語の設定場所」「ブレークポイントバーの位置」「Base背景のグラデ塗りの操作」が操作レベルで欠落。多くの具体操作が後続章送りのため、本章単体の作業量は少なく、致命的詰まりは無いが、上記を補えば完全に再現可になる。

## ch-g2 — 2. デザイントークン（全体共通） （判定:一部詰まる / blocker:2）
> トークン台帳としての数値・色・命名は非常に丁寧で、§2.1 カラー登録手順と §2.4–2.6 の台帳は初心者でも値を引いて手入力できる水準。ただし「実際に Studio で操作する」視点で詰まる箇所が複数ある。最大の詰まりは (1) text-transform:uppercase（English Label の必須要件）の Studio 操作が本章にも §0.4 変換表にも無いこと、(2) Header の Backdrop filter（ぼかし）が「必要」とだけ書かれ操作も Free/Mini 代替も示されないこと。加えてフォント追加の前提で「任意のテキスト要素を選択」とあるが空キャンバスにテキストを置く手順が無い、グラデ文字・有機ブロブの Free 代替（SVG Embed／回転で近似）に具体的なコード・操作が無い、レスポンシブ縮小値が「約70%／約50%」と曖昧、などが残る。台帳としては実用的だが、操作手順としては手当てが要る。
- **[blocker]** §2.2 標準9スタイル表 #7 English Label「text-transform: uppercase」／完了チェック「English Label に text-transform: uppercase を設定した」
  - 問題: uppercase 化が必須要件として2回出るが、Studio のどこで text-transform を設定するのか本章にも §0.4 変換表にも記載が無い。初心者は『どのパネルの何を押せば大文字化できるのか』が分からず、要件を満たせない。
  - 修正: 右パネル テキスト（Text）タブ内のどの欄（例: Typography の大文字小文字/Case オプション）で uppercase を選ぶかを明記する、または §0.4 変換表に text-transform の対応を追加する。
- **[blocker]** §2.1-C #21 bg/header 注記「別途 Backdrop filter でぼかしを併用（§2.6 注記）」／§2.6 制約「Header背景の『ぼかし』は…Backdrop filter（背面フィルター・Firefox非対応）で実装する（フォールバック設計が必要）」
  - 問題: Backdrop filter（背面ぼかし）が『必要』『フォールバック設計が必要』とだけ書かれ、Studio でどのパネル/メニューから設定するのか、Free/Mini のどちらでどう実装するのか（操作・コード・貼り先）が一切示されていない。§0.4 変換表にも無い。初心者はヘッダーのぼかしを実現できず手詰まり。
  - 修正: Backdrop filter を Studio のどこで設定するか（例: 該当 Box の外観/エフェクト欄）を明記、不可なら Mini=Custom Code(Head) に注入する backdrop-filter:blur(...) の具体値と対象クラスを示し、フォールバック（不透明背景色）の具体策も書く。
- **[major]** §2.2「前提: フォント追加」手順1「任意のテキスト要素を選択 → 右パネル テキスト（Text）タブ」
  - 問題: 本章はプロジェクト最初の共通設定であり、この時点ではキャンバスにテキスト要素がまだ無い前提。空キャンバスから『テキスト要素を1つ置く』手順（どのツール/メニューで追加するか）が抜けており、初心者は『何を選択すればいいのか』で止まる。§2.2 登録手順の step1 には『テキスト要素を1つ置き』とあるが、それより前のフォント追加節で既に選択を要求している順序矛盾もある。
  - 修正: フォント追加の前に『キャンバスにテキスト要素を1つ追加する』操作（追加メニュー/ショートカット等の具体手順）を先頭に置き、以降の選択対象を明確にする。
- **[major]** §2.2 登録手順 step4「テキスト要素選択時にスタイルバー上部へ出る『スタイル』項目をクリック」／§2.1 同様の『スウォッチをクリック』
  - 問題: 『スタイルバー上部』がどのパネルのどこを指すのか不明確。右パネルなのか上部バーなのか、どのアイコン/ラベルを押すと登録ダイアログが出るのかが特定できず、初心者は登録ボタンを探せない。
  - 修正: スタイル登録ボタンの正確な位置（例: 右パネル上部の『スタイル』ドロップダウン → +登録）を画面位置とラベルで特定して記述する。
- **[major]** §2.5 Free代替「FV 下線の手書き風ハイライトは別 Box（角丸 4 隅個別＋少し回転）で近似」
  - 問題: 『少し回転』の回転操作（Studio のどこで角度を入れるか）が本章にも §0.4 変換表にも無く、回転量の数値も無い（『少し』）。グラデ/ブロブの SVG Embed も実際の SVG コードや貼り先が示されず、初心者は近似の作り方が分からない。
  - 修正: 回転は Studio のどのパネルで何度入れるか（具体角度）を明記し、SVG Embed は最小の貼付コード例と貼り先（Embed 要素のコード欄）を示す。
- **[minor]** §2.3 レスポンシブ表 English Number L「約 70% に縮小」「約 50% に縮小（vc-big 180→90px 目安）」、Footnote Mobile「10–11px」
  - 問題: Size は px 入力なのに『約70%／約50%』と相対表現で、初心者は何 px を入れればよいか確定できない（vc-big の例だけ90px と分かるが他要素は不明）。Footnote も範囲指定で1値に決められない。
  - 修正: 代表要素ごとに Tablet/Mobile の確定 px 値を併記する（例: perk96→Tablet 67px/Mobile 48px 等）。Footnote は1値に固定する。

## ch-t10 — 10. 公開前 QA チェックリスト （判定:一部詰まる / blocker:0）
> 本章は「作る」章ではなく公開前の確認票（チェックリスト）で、大半の項目は「〜になっているか目視する」という確認タスク。そのため §0.4 変換表で詰むタイプの該当は少なく、UI 位置の明示も比較的よい（10.5「右パネル→設定タブ→リンク設定」、10.6「フォームダッシュボード→設定」「プロジェクトダッシュボード Apps」、10.7「Project 設定→公開サイト基盤」など）。ただし初心者が確認操作そのものに詰まる箇所が複数ある。最大のものは 10.7 の「HTML ソースに generator=Studio.Design.HRC が出るか」で、初心者はブラウザでソースを見る方法を知らない。次いで JSON-LD の Custom Code 設置（貼るコードも貼り先パネルの開き方も無し）、コントラスト／タップ領域 44px／hover 残留などの確認に使うツールや手段が示されていない点。値の曖昧さ（「100KB 以下目安」「概ね 44×44px」「設計どおり」）も散見。重大ブロッカー（これが無いと公開作業が止まる）は無く、確認の取りこぼしリスクに留まるため verdict は「一部詰まる」、blockers=0。
- **[major]** 10.7 公開基盤（最重要）『公開 URL の HTML ソースに generator=Studio.Design.HRC が出る』
  - 問題: (a)(i) 新旧基盤判定の核がHTMLソース確認だが、初心者は『ブラウザでHTMLソースを表示する方法』『どこをどう検索するか』を知らない。右クリック→ページのソースを表示、Cmd+U、Ctrl+F検索などの具体手順が一切ない。判定の入口で詰まる。
  - 修正: 『公開URLを開き、右クリック→ページのソースを表示（または Cmd+U / Ctrl+U）→ Cmd+F で generator を検索』と確認手順を1行で明記する。
- **[major]** 10.7 計測タグ・構造化データ『JSON-LD 構造化データを head に <script type="application/ld+json"> で設置（標準 UI なし・Custom Code 経路）』
  - 問題: (g)(a) Custom Code パネルをどこから開くか（どのメニュー/タブ）が書かれておらず、実際に貼り付ける JSON-LD のサンプルコードも無い。『標準UIなし・Custom Code経路』とだけあり初心者は手詰まり。
  - 修正: Custom Code 入力欄の開き方（例: 右パネル→ページ設定→Custom Code、head/body の区別）と、貼り付ける JSON-LD の最小サンプルを1つ提示する。
- **[minor]** 10.7 メタ『計測タグ…head / body の Custom Code に投入』
  - 問題: (a) GA4/GTM を head/body の Custom Code に入れる、とあるがその Custom Code 入力欄の場所（サイト全体 head か、ページ単位か、どのパネル）が未提示。JSON-LD と同じく入口不明。
  - 修正: head 用 Custom Code 入力欄の正確な場所（サイト設定の head セクション等）を1行で示す。
- **[minor]** 10.9 アクセシビリティ『カラーコントラストが WCAG AA を満たす』『フォーカスインジケータが視認できる』
  - 問題: (a)(d) コントラスト比をどう測るか（使うツール名・手順）が無い。WCAG AA の基準値（4.5:1 等）も未記載で、初心者は『満たすか』を判定できない。focus リング設計値は示されるが確認手段は不明。
  - 修正: コントラスト確認の具体手段（例: ブラウザDevToolsのコントラスト表示、WebAIM Contrast Checker等）と AA の合格基準値を併記する。
- **[minor]** 10.4 タッチ・操作性『タップ領域が概ね 44×44px 以上』『隣接…8px 以上の間隔』
  - 問題: (d)(i) 『概ね』とあり、実機で px をどう測るか手段が無い。初心者は目視で 44px/8px を判定できず、合否を付けられない。
  - 修正: ブラウザのレスポンシブモード/DevToolsで要素サイズを確認する手順を1行添えるか、エディタ上で対象要素のサイズ表示を見る方法を示す。
- **[minor]** 10.4『カード hover の translateY がタップ後に残らない』ほか hover 残留チェック
  - 問題: (i) 残留していた場合に『どう直すか』への導線が無い（§11 のような対応番号併記が無い）。確認はできても初心者は是正に進めない。
  - 修正: hover 残留・固着が見つかった場合の対処（または対処を扱う節への参照）を1行で示す。
- **[minor]** 10.10 パフォーマンス『VC ロゴ画像が圧縮済み（各 100KB 以下目安）』『Lighthouse Performance 80+』
  - 問題: (a)(d) 画像サイズの確認方法・Lighthouse の起動方法（DevTools のどこ、モバイル基準の設定）が未記載。『目安』『目標』で合否境界も曖昧。初心者は計測自体に詰まる。
  - 修正: Lighthouse の開き方（Chrome DevTools→Lighthouseタブ→Mobile→分析）と画像サイズ確認手段を1行ずつ補う。
- **[minor]** 10.7 公開基盤『独自ドメイン接続時、A レコードを 34.111.141.225 に更新済み』
  - 問題: (b)(c) 『A レコード』はDNS用語で本ガイド/§0.4 に説明が無く、どこで（ドメイン管理側）更新するかも Studio 操作外。初心者には何をどこで触るか不明。ただし独自ドメイン時のみの条件項目。
  - 修正: A レコードがドメイン取得業者側のDNS設定であること、更新は『独自ドメイン接続時のみ・DNS管理画面で実施（詳細はドメイン設定の章/業者手順を参照）』と一言補う。

## ch-t11 — 11. モバイル実装の落とし穴（v10 ベース監査） （判定:一部詰まる / blocker:3）
> 本章は「監査・落とし穴の指摘＋対処方針」型で、原物 CSS の構造的破綻（display:contents+order、white-space:nowrap、疑似要素、fixed+JS スクロール制御など）を正しく洗い出している点は優秀。重要度ラベルと着手順、§0.4 でカバー済みの操作（gap/padding/枠線/折返し/z-index 等）への落とし込みも多くは妥当で、その範囲は初心者でも引ける。ただし本章は「何をどのメニューでクリックするか」という実操作の粒度では書かれておらず、初心者が単独で再現するには重い箇所が複数ある。特に(1)章全体の中核操作である「条件スタイル（BP 別上書き）」の具体的な出し方・有効化手順が本章内に無く #term-conditional 任せ、(2)Toggle/Loop Box の具体的な配置・パネル操作が他章前提で、本章では結線挙動だけ要求、(3)「DOM を最初からモバイル順に組む／複製して表示・非表示で出し分ける」という設計判断を初心者に委ねている点、(4)画像化（SVG/PNG ベイク）の作り方・アップロード先が具体でない点が詰まりどころ。値は大半が具体的だが、aspect-ratio・object-fit の Studio 対応が「未検証」のまま代替手順が条件分岐で曖昧な箇所がある。致命級の設計依存（FV 並べ替え・float-perk）は方針は妥当だが初心者単独での実装は現実的に困難で、blocker として 3 件計上。
- **[blocker]** 11.0 / 表「Studio 写像先」列および補足「構造的な点だけ条件スタイルで上書き」
  - 問題: 本章の対処はほぼ全て『Mobile 条件スタイルで上書き』に依存するが、条件スタイルを Studio のどこでどう出す/有効化するか（BP を切り替えてから値を変える＝上書きになる、という基本操作）が本章内に説明されず #term-conditional 任せ。初心者は『条件スタイル設定』と書かれても、どの画面でモード切替するのか分からず最初の一歩で詰まる。
  - 修正: 本章冒頭に『画面上部の Default/Tablet/Mobile 切替を Mobile にしてから右パネルで値を変えると、その BP だけの上書き（オレンジ表示）になる』という 1 ステップの基本操作を明記し、以降は『Mobile 上書き』をその手順への参照にする。
- **[blocker]** 11.2a モバイルの要素並べ替え（order）が display:contents 依存 [致命] 対処
  - 問題: 『DOM を最初からモバイル順に組む』『吸収不可なら複製＋表示/非表示方式に切替え』という二択の設計判断を初心者に丸投げしている。どちらを選ぶかの基準が『PC のグリッド配置で吸収できる範囲か実機検証』としか書かれず、検証して切り替えるという高度判断・複製運用は初心者には実行不能。『表示/非表示（目アイコン）』もどのパネルのどのアイコンか本章では未説明。
  - 修正: FV について推奨レイアウト（縦 Flex でモバイル順に固定し PC を 2 カラム grid で再現する具体レイヤー構成）を 1 つに決め打ちで手順化し、複製方式は『どうしても無理な時の最終手段』として手順とコピー同期チェックリストまで具体化する。
- **[blocker]** 11.12a position:fixed＋スクロール連動の表示制御 [致命] Mini 推奨 / Free 代替
  - 問題: 致命項目の最確実策が『カード全体を Custom Code/Embed（HTML+CSS+JS）で丸ごと注入。元 JS をほぼ流用』だが、貼り付ける実コードも貼り先（Embed をどこに追加するか、Body 注入の場所）も本章に無い。Studio 初心者かつ『手元はこの章＋§0.4 のみ』の前提では、元 JS の所在も注入手順も分からず手詰まり。Free 段階は『一旦オフ』で逃がせるが、最終的に誰かが実装せねば公開できない致命項目が宙に浮く。
  - 修正: 注入する HTML+CSS+JS の実コード（またはその全文がある参照先ファイルパス）と、Studio で Embed/Custom Code を追加する画面手順（追加メニューの場所・Body 注入位置）を本章に具体提示する。
- **[major]** 11.9b アコーディオン＝ Toggle 化 / 11.1a ハンバーガー Toggle / 11.2e Loop Box
  - 問題: Toggle・Loop Box の『追加 → 基本タブ → インタラクション → Toggle』までは一部書かれているが、Toggle の button/content にどう中身を入れるか、Show by default や状態差（open 時の影・border・矢印回転）を右パネルのどのタブで設定するかが本章では断片的。『変形タブ→アニメーション .3s』も操作粒度が粗く、初心者は『で、回転はどこに数値を入れる？』で止まる。
  - 修正: Toggle の content への要素配置、状態（open/close）別スタイルの設定パネル、矢印回転の入力箇所を 1 度だけ図つきで手順化し、11.1a/11.9b/11.2e から参照する。
- **[major]** 11.8b カバー写真 16:10 固定比とフォーカル 35% / 11.7a aspect-ratio:5/2
  - 問題: object-fit 相当・aspect-ratio の Studio 対応が『未検証』『あれば使用、無ければ固定高 or パディングハック』と条件分岐のまま。初心者は『未検証』『無ければ』と言われても判断・分岐ができず、『パディングハック』の具体手順も無い。
  - 修正: Studio の縦横比固定 UI とフィット指定の有無を確定記載し、無い場合の代替（事前トリミング推奨を既定にする等）を分岐なしの単一手順に落とす。パディングハックを使うなら具体値つきで示す。
- **[major]** 11.2c / 11.5a / 11.8a 等で繰り返される『1 枚の SVG/PNG にベイクし Image 配置』『画像化』
  - 問題: 疑似要素・装飾を『画像にベイクして Image 配置』という代替が多数あるが、誰がどのツールでベイクするのか、書き出した画像を Studio のどこ（追加メニューの Image／アップロード先）に置くのかが本章に無い。SVG 実体パスがある項目（laurel.svg, cta_illust_woman.svg 等）は手掛かりがあるが、十字コネクタ・赤キャプション＋ティックなど『新規にベイクが必要』なものは元データも作成手順も無く、初心者は作れない。
  - 修正: 画像化が必要なものを一覧化し、(a) 既存アセットパスがあるもの (b) 新規作成が必要なものを区別。新規分は作成担当・書き出し仕様（サイズ/形式）と Studio へのアップロード手順を明記する。
- **[minor]** 11.6b 数字＋単位のフォント混在『リッチテキストか…2 要素で』
  - 問題: 『リッチテキスト』は §0.4 変換表に無い用語で、Studio 上の操作（1 つの Text 内でサイズ違いを作る方法）が示されない。初心者は 2 要素方式に倒すしかないが、その baseline 揃え（『2 要素 baseline 揃え』）も配置メニューのどの設定か不明。
  - 修正: 『数字 Text＋単位 Text を横並び Box に入れ、配置を下端揃え』という具体操作に一本化し、リッチテキスト案は削除するか操作手順を添える。
- **[minor]** 11.13 横断チェック 表#7『clamp は固定 px or BP 別へ展開』/ 11.2b clamp(26px,7.8vw,36px)
  - 問題: clamp() の vw 値（7.8vw 等）を『固定 px か BP 別へ展開』せよとあるが、展開後にどの BP でいくつの px を入れるか（中間値の決め方）が初心者に委ねられている。11.2b は最小/最大 px はあるが Mobile 540 で具体的に何 px を入れるかが曖昧。
  - 修正: 主要見出し（h1/section-title/lead）について、Default/Tablet/Mobile/Mini の各 BP で入れる固定 px を表で確定提示する。
- **[minor]** 11.13 横断チェック 表#5『親 auto＋子 % が効かない／配置「均等」が親 auto 幅で無効』(11.4b/11.6a でも反復)
  - 問題: 重要な落とし穴だが対処が『親幅を固定/100% に』と原則のみ。初心者には『親』がどのレイヤーか（rec-grid 等の特定はあるが、一般則として自分の構造でどれが親か）と、Studio で幅を 100% にする操作（§0.4 の Fill=親いっぱい と同義かどうか）が結びつかない可能性。
  - 修正: 『親 Box を選び、幅を Fill（親いっぱい）または固定 px にする＝§0.4 のサイズ操作』と変換表へ明示的に紐付け、Fill と 100% の関係を一言補足する。

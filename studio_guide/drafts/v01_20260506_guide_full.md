### 1.2 フォント設定（Studio 標準・Font List 経由）

> ✅ Free プラン対応。Custom Code は使いません。

> 📍 **実装現状**（2026-05-07 公開サイト解析）:
> - Font List 構成: **Lato（Studio 標準・残存）/ Noto Sans JP（追加済）/ Inter（追加済）**
> - Noto Sans JP のウェイト: 200/300/400/500/600/700/800/900（豊富）
> - Inter のウェイト: 同程度に豊富（italic 含む）
> - **要確認**: Font List 最上部が Noto Sans JP に切替済か（ユーザー確認では「なってる」との回答だが、公開HTMLでは Lato が先頭に列挙される。Studio 内のデフォルトフラグは別管理のためこれで OK の可能性高い）
> - **Lato は削除しなくて OK**（テキスト要素は明示的に Noto Sans JP / Inter を指定するため、Lato が残っていても影響なし）

**Studio の仕組み**: 「**Font List の最上部にあるフォント = デフォルトフォント**」。新規作成するテキスト要素に自動適用されます。新規プロジェクトの初期デフォルトは `Lato` なので、これを Noto Sans JP に置き換えます。

| 用途 | フォント | ウェイト | 適用方法 |
| --- | --- | --- | --- |
| 本文（日本語）・デフォルト | **Noto Sans JP** | 400 / 500 / 700 / 800 / 900 | Font List の**最上部**に配置 |
| 見出し・数字（英字） | **Inter** | 500 / 700 / 800 / 900 | Font List に追加し、必要要素で個別選択 |

#### 手順 Step A — Noto Sans JP を Font List に追加

1. キャンバス上に**任意のテキスト要素を1つ追加**（仮で「テスト」と入力）
2. そのテキストを選択した状態で、右パネルの **スタイルバー → Text タブ** を開く
3. フォント名の表示部分をクリック → **「Add Font」** ボタンをクリック
4. ダイアログで「**フォントサービス**」を **Google Fonts** に切替
5. 検索ボックスに **`Noto Sans JP`** と入力
6. 候補から「Noto Sans JP」を選択 → 確定
7. Font List に追加されたことを確認

#### 手順 Step B — Inter も同じ要領で追加

- Step A と同じ手順で **`Inter`** を追加（英字・数字用）

#### 手順 Step C — Noto Sans JP を Font List の最上部にドラッグ

1. Font List のパネルで現在のデフォルト（**Lato が最上部**にあるはず）を確認
2. **Noto Sans JP をリストの最上部にドラッグ＆ドロップ**
3. これで Noto Sans JP がデフォルトフォント化 → 新規要素に自動適用

#### 手順 Step D — テキストスタイルとして登録（左サイドバー → スタイル）

> 📍 **正しい UI パス**: Studio Editor 5.0 の「スタイル管理」は**画面左サイドバー**にあります（前版で「画面右上のデザイン設定」と書いていたのは誤り。訂正済み）。

1. **左サイドバーの「スタイル」アイコン**をクリック（左サイド縦並びのアイコン群の中、「レイヤー」の下あたり）
2. 開いたパネルで **テキスト** タブを選択
3. キャンバス上で対象テキスト要素（仮テキスト）を選択
4. テキスト要素のフォントを Noto Sans JP に、サイズ・行高を設定
5. 上部メニューの「スタイル」が **「未設定」** と表示されている箇所で **「テキストスタイルとして登録」** をクリック
6. ラベル名を付与（例: `Body` / `H1` / `Section H2` / `Lead` など）
7. 同様に Inter を使う見出し用も別ラベルで登録（例: `English Label`）

#### 副フォント（Sub Font）— 日本語サイトで便利

Studio には「**副フォント**」機能があり、メインフォントが日本語非対応の場合に自動的に副フォントを当てられます。

- 例: メイン = Inter（英字メイン）/ 副 = Noto Sans JP
- → 英字数字は Inter、日本語は Noto Sans JP に自動切替
- ⚠️ Studio の言語設定が**日本語アカウント**である必要あり

本プロジェクトでは:
- **メイン**: Noto Sans JP（日本語コピーが大半のため）
- **必要に応じて Inter を要素単位で適用**（h1 の「FV」サブラベル、Record の数字、Inter 系の英文ラベル等）
- 副フォント機能は**任意**（必要なら設定）

#### 制限事項

- ❌ **フォントのアップロード・インポートは非対応**（独自フォント不可）
- ✅ Google Fonts / Adobe Fonts / TypeSquare 等の**サービス内フォント**のみ
- ✅ Noto Sans JP / Inter は Google Fonts 経由で問題なし

> ℹ️ **過去版の訂正（2026-05-06）**: 当初「Page 設定 → デフォルトフォント」と書いていましたが Studio に該当 UI はなく、正しくは「Font List の最上部 = デフォルトフォント」でした。本節は公式ヘルプに基づく正確版です。

### 1.3 ボディ全体のスタイル設定（`<Base>` レイヤー経由）

> ✅ Free プラン対応。Custom Code は使いません。
> 📍 **仕組み**: Studio に「Page 設定 → Default Background / Default Text Color」のような専用 UI はなく、ページ最上位コンテナの **`<Base>` レイヤー**を選択して上部スタイルバーから設定します。

#### Step 1.3.1 — `<Base>` レイヤーを選択

1. **左サイドバー → 「レイヤー」アイコン**をクリック
2. レイヤーパネルで**最上位の `<Base>`** をクリック
3. 上部スタイルバーが「Base 用」に切替わる

#### Step 1.3.2 — 背景色を設定 `#FCFDFF`

1. `<Base>` を選択した状態で、上部スタイルバーの **「塗り (Fill)」** にカーソルを当てる
2. メニュー → **「カスタム」**タブ → HEX 値ボックスに **`#FCFDFF`** 入力
3. または §2.1 で `bg` カラースタイル登録済みなら、そこから選択
4. 別の場所をクリックして確定

#### Step 1.3.3 — デフォルト文字色を設定 `#0F1A33`

1. `<Base>` を選択した状態で、上部スタイルバーの **「文字色」**（テキスト関連項目）
2. HEX 値ボックスに **`#0F1A33`** 入力
3. または §2.1 で `ink` カラースタイル登録済みなら、そこから選択

> 💡 `<Base>` の文字色は子要素に**継承**されます（子が個別に色設定していない限り）。

#### Step 1.3.4 — デフォルトフォント = §1.2 で完了済み

§1.2 で Font List 最上部に Noto Sans JP を配置済み。**§1.3 で再設定する必要なし**。

#### Step 1.3.5 — デフォルト行高 = §2.2 のテキストスタイルで管理

行高は単一 Page 設定ではなく **テキストスタイル経由**で管理（Studio 流）:

- §2.2 の「Body」テキストスタイル登録時に `line-height: 1.7` を指定
- 各セクションの本文・リード・カード本文に該当スタイルを適用すれば自動で 1.7

→ §1.3.5 単独で何もせず、§2.2 で対応します。

#### word-break / line-break について

v09 では `word-break: keep-all; line-break: strict;` を body 全体に適用（日本語の途中改行抑制）。Studio 標準ではこのレベルの制御は不可。

| 案 | 内容 | おすすめ |
| --- | --- | --- |
| **A. 諦める** | Studio 標準のまま。Mobile レビューで気になる箇所のみ手動改行調整 | ✅ 推奨 |
| **B. Embed で部分対応** | Hero h1 などこだわりたい箇所だけ Embed で `<style>` を書く（h1 は §9.2 Embed 内で word-break 含めれば自動解決） | 重要見出しのみ |
| **C. 全体を Embed 化** | 範囲外 | ❌ 非推奨 |

#### Step 5 — Right Box に CTA 2 ボタンを配置

> 📍 **矢印アイコンの配置方式について**: v09 mockup では絶対配置（`position: absolute; right: 12px`）でしたが、Studio で実装する場合は **flex の子要素として矢印 Box を兄弟配置 + 配置-水平「均等」（= space-between）** が現実的です。本指示書は **flex 配置版**を主に記述（v09 の絶対配置版を使う場合の差分も併記）。

> ⚠️ **Studio で「均等」（space-between）を視覚化するには幅固定が必須**（2026-05-07 実装で確認）
>
> - Studio の flex 親 Box が「幅 auto」だと、内容にぴったりサイズになるため、items を端に push する余地がない
> - 「均等」設定をしても items が**くっついて見える**
> - **解決**: ボタン本体（Box）の幅を**固定値**にする
>
> ##### 推奨幅の計算（Noto Sans JP 13px 800 想定）
>
> 必要幅 = `padding-left + テキスト幅 + Gap（テキストと矢印の隙間）+ 矢印幅 + padding-right`
>
> | ボタン | テキスト幅 | パディング | 矢印 | Gap 目標 | **推奨幅** |
> | --- | --- | --- | --- | --- | --- |
> | 無料相談（4文字）| ~56 px | 28+12 | 22 | ~17 px | **`135 px`** |
> | 資料ダウンロード（8文字）| ~102 px | 24+12 | 22 | ~20 px | **`180 px`** |
>
> ※ フォントレンダリングで多少ずれます。実際の見た目で **±5-10 px** 微調整してください。

##### 📚 Studio の「配置 - 水平」プルダウン選択肢の対応表

| Studio 表記 | CSS justify-content | 用途 |
| --- | --- | --- |
| 左寄せ | `flex-start` | items を左に寄せる |
| 中央寄せ | `center` | items を中央に寄せる |
| 右寄せ | `flex-end` | items を右に寄せる |
| **均等** | **`space-between`** | **両端配置・端には余白なし**（CTA ボタンで使用）|
| 均等（余白含む） | `space-around` または `space-evenly` | 両端にも等しい余白 |

##### 共通の落とし穴

| 症状 | 原因 | 対処 |
| --- | --- | --- |
| 配置「均等」にしても矢印が右端に行かない | **ボタンの幅が `auto`** で固定されていない（auto だと items を端に push する余地がない）| ボタンの **幅を固定値**に（無料相談 = `135 px` / 資料DL = `180 px`、Gap 目標 17-20px）|

| 配置プルダウンに「両端揃え」が無い | Studio では **「均等」が space-between 相当** | プルダウンから **「均等」** を選択 |

  - 上: テキスト・CTAタグ
  - 下: フォーム

### 7.4 タッチ操作・hover 配慮

Mobile・Tablet（タッチデバイス）では:
- カード hover アニメーション（translateY）は無効化推奨
  - Studio で Mobile breakpoint 時は hover プロパティを未設定にする
- ボタン hover の色変化は維持（タップ時に視覚フィードバック）
- VC ロゴマーキーの「hover で停止」は touch-device では効かないので注意（Mobile では再開できない場合あり）

### 7.5 タップターゲットサイズ

- すべてのリンク・ボタンは **最低 44×44px のタップ領域**を確保（iOS HIG / WCAG 2.5.5）
- テキストリンクが小さい場合は padding を追加して十分な領域を作る
- 隣接タップターゲット間に **最低 8px の間隔**

### 7.6 viewport / Safe Area

- meta viewport は v09 通り: `<meta name="viewport" content="width=device-width, initial-scale=1.0">`
- iPhone のノッチ・Home Indicator 対策:
  - Footer に `padding-bottom: max(32px, env(safe-area-inset-bottom))` を追加
  - 固定ヘッダーは `padding-top: env(safe-area-inset-top)` を考慮（背景色を上端まで延長）

## 9. Studio 特有の注意点・Embed コンポーネント

> ✅ **Free プラン前提**: 本章は **Embed コンポーネント**（全プラン対応）を使う前提で記述します。Custom Code（Head/Body、Mini プラン以上限定）は使いません。

### 9.0 Embed コンポーネントとは（前提）

Studio の Embed は、デザインエディタ上に配置できるコンポーネントの一つで、HTML / CSS / JavaScript を直接書き込めます:
- ツールバーの **`</>` アイコン** から配置
- Box と同じように位置・サイズ・配置を Studio 上で制御
- 内部の `<style>` は **その Embed のスコープに限定される**わけではない（グローバルに効く場合もあるが、テスト推奨）

### 9.3 ~~Embed B: VC ロゴマーキー~~ → **Loop Box に置換**

> ⭐ **重要更新（2026-05-07）**: VC ロゴマーキーは Embed ではなく **Studio ネイティブの Loop Box コンポーネント**を使用します。Embed 不要。
>
> Loop Box の詳細は [`../studio_spec.md` §3.3.2](../studio_spec.md) 参照。
> 実装手順は本指示書 §5-7 VC Partners セクション内に記述。

**Loop Box を使う理由**:
- ✅ Free プランで利用可能
- ✅ Studio エディタ内でアニメーションをプレビューできる（Embed と異なり）
- ✅ 子要素は通常の Image / Box として配置・編集できる（URL 置換不要）
- ✅ Pause on hover が標準機能
- ✅ 速度（px/s）・方向を GUI で簡単に調整

**Loop Box への移行手順**（VC ロゴマーキー）:

1. Hero or VC セクション内に **Loop Box** を配置（追加 → 基本 → インタラクション → Loop Box）
2. Loop Box の右パネルで:
   - 速度: `60 px/s`（デフォルト、必要に応じて調整）
   - 方向: 横（→）
   - Pause on hover: ON
3. Loop Box の中に **Image** を 12 個配置（VC ロゴ各社）
   - 各 Image は 200×80 px（PC）/ 160×64 px（Mobile）
   - object-fit: contain（Studio の画像表示設定で）
4. Loop Box は子要素を自動複製してシームレスループするので、**12 社分だけで OK**（Embed のように×2 する必要なし）

→ 旧 Embed B 版のコードは保管参考のため §9.7（後述）に移動。

### 9.5 Studio で苦手な機能の代替（Free プラン版）

| HTML/CSS 機能 | Free プランでの代替 |
| --- | --- |
| `clamp(min, vw, max)` | Studio のブレークポイントごとに値を直接指定（推奨） or Embed |

| word-break / line-break | Studio 標準には無い → 必要箇所のみ Embed で個別対応 |
| Custom Code (Head) ❌ | **Free では使用不可**。すべて Embed に分散 |

## 11. モバイル実装の落とし穴と対処（v09 ベースの監査結果）

v09 の CSS を実機サイズで監査した結果、Mobile で**そのままだと壊れる**箇所と、Studio 実装での対処を以下にまとめる。**§7 の table とセットで参照**。

### 11.1 🔴 Hero h1 の `white-space: nowrap`

- **箇所**: v09 line 138 `.hero h1{...white-space:nowrap}`
- **問題**: 「挑戦するスタートアップに、補助金という追い風を。」が1行で表示されようとして Mobile で画面外にはみ出す
- **対処**:
  - Studio Mobile breakpoint で `white-space: normal` に上書き
  - h1 をテキストオブジェクトとして配置し、Mobile で改行点を `<br>` で明示的に挿入
  - 推奨改行: `挑戦するスタートアップに、` / `補助金という追い風を。`（2行）または `挑戦する` / `スタートアップに、` / `補助金という` / `追い風を。`（4行・更に小さい画面用）

### 11.2 🔴 Hero Inner の grid 1.5fr .85fr が Mobile で破綻

- **箇所**: v09 line 133 `.hero-inner{display:grid;grid-template-columns:1.5fr .85fr;...}`
- **問題**: Mobile で 2カラムを維持すると VC Perk Card が異常に細くなり、内部の vp-compare が読めなくなる
- **対処**: Mobile では `grid-template-columns: 1fr` に変更し、`gap: 32px → 24px` 縦並びに。順序: hero-left → stat-panel（VC Perk Card）

### 11.3 🔴 VC Perk Card の vp-compare 比較表が Mobile で潰れる

- **箇所**: v09 line 278-307（vp-row, vp-items 等）
- **問題**: 比較表は `grid-template-columns: 34px 1fr`（左ラベル + 右items）の中で 6セル横並び（着手金 / + / 成功報酬 / + / 採択後支援 という構成）。Mobile 幅では各セルが 30px 弱になり数字がはみ出す
- **対処**: 2案
  - **案A（推奨）**: Mobile で各 vp-items を縦並びに変更（`flex-direction: column`、`+` プラス記号は非表示）。「着手金」「成功報酬」「採択後支援」の3項目を縦に列挙。比較行2つ（通常/特典）も縦に積む
  - **案B（簡略化）**: Mobile では比較表を**通常行を非表示**にし、特典行のみ表示。「特典: 着手金0円・成功報酬10〜15%・採択後支援3〜5%」を1行で表示

### 11.4 🟡 Hero ロゴマーキーの位置と高さ

- **箇所**: v09 line 187-260（hero-marquee-band）
- **問題**: Mobile で hero が縦スタックされると、marquee がスクロール下に出てしまう。`min-height: 100vh` の hero との関係で「FVに含まれて見えない」事態になり得る
- **対処**:
  - Mobile では hero `min-height` を解除（`min-height: auto` または `min-height: 0`）
  - ロゴマーキー帯は hero 末尾の通常配置で OK
  - ただし「FVのスクロール無し閲覧」を優先するなら、Mobile では Service Perk Banner より上のどこかに移動も検討

### 11.5 🟡 Header の Nav 6項目が Mobile で収まらない

- **箇所**: v09 line 569-580
- **問題**: Header height 68px の中に Logo + Nav 6項目 + CTA 2つは Mobile では物理的に入らない
- **対処**: 必須でハンバーガーメニュー化（§7.3.1 参照）
  - Studio の Hamburger Menu コンポーネントを使う
  - 展開時は overlay（背景 ink, 90%）+ Nav 縦並び + CTA 縦並び

### 11.6 🟡 Section padding 120px 0 が Mobile で過大

- **箇所**: v09 line 327 `.sec{padding:120px 0}`
- **問題**: Mobile で 120px のセクション間余白は冗長で、スクロール量が無駄に増える
- **対処**: Mobile で `padding: 72px 0` に縮小（VC・CTA は 80px 0）

### 11.7 🟡 各カード padding が Mobile で過大

- **箇所**: 全 .prob-card / .appr-card / .svc-card / .case-card 等
- **問題**: Mobile 幅 375px の中で padding 32〜36px だと中身の領域が 311〜307px と窮屈
- **対処**: §7.3 の各セクション仕様に従い 24px 前後に縮小

### 11.8 🟡 Service Perk Banner の grid 1fr auto

- **箇所**: v09 line 377 `.perk-inner{...grid-template-columns:1fr auto;...}`
- **問題**: Mobile で右側「0円」表示の幅が auto だと中途半端な位置
- **対処**: Mobile で `grid-template-columns: 1fr` に変更し縦スタック。「0円」は中央寄せ・border-left は border-top に変更

### 11.9 🟡 CTA Inner の grid 1.1fr 1fr

- **箇所**: v09 line 513 `.cta-inner{...grid-template-columns:1.1fr 1fr;...}`
- **問題**: Mobile で 2カラムだとフォーム入力欄が極小化
- **対処**: Mobile で `grid-template-columns: 1fr` で縦スタック

### 11.10 🟡 Form の padding 44px 40px

- **箇所**: v09 line 522 `.form{padding:44px 40px;...}`
- **問題**: Mobile で内部の input + label + button + consent が窮屈
- **対処**: Mobile で `padding: 28px 24px` に縮小

### 11.11 🟡 Footer FT Inner の grid 1.3fr 2fr

- **箇所**: v09 line 538
- **問題**: Mobile で会社情報と Nav が2カラムだと長い会社情報が読みにくい
- **対処**: Mobile で `grid-template-columns: 1fr` で縦スタック

### 11.12 🟡 Footer Nav の repeat(3,1fr)

- **箇所**: v09 line 543
- **問題**: Mobile で 3カラムだと各カラムが 100px 程度になりリンクテキストが折返し多発
- **対処**: Mobile で `repeat(2, 1fr)` または 1fr スタック

### 11.13 🟡 Hero block-1 / block-2（背景blob）が Mobile で配置崩れ

- **箇所**: v09 line 130-131
- **問題**: 絶対配置で `width: 46%` / `width: 32%` だが Mobile では崩れて中身に被ったり画面外に出すぎたり
- **対処**: Mobile で `display: none` か、サイズと位置を調整（block-1 は `width: 70%; right: -20%`、block-2 は `width: 50%; left: -10%` 等）

### 11.14 🟡 VC Head Box の `vc-big` 50+ 表示が 180px

- **箇所**: v09 line 415
- **問題**: Mobile で 180px は画面幅の半分超で、vc-big の左右の装飾円も含めるとはみ出す
- **対処**: Mobile で `font-size: 100〜120px`、装飾円のサイズも縮小

### 11.15 🟡 Service h2 / Approach h2 等の「文字スパン chunk」改行

- **箇所**: 各セクション h2 の `<span class="chunk">...</span><br class="br-tablet">...`
- **問題**: Studio で `<br class>` を直接入れにくいケース（Studio の Text 要素に class 付与が制限される場合）
- **対処**: 各 h2 を「Mobile 用」「Tablet 用」「Desktop 用」の3パターン Text オブジェクトとして配置、ブレークポイントごとに表示切替。または Studio の Custom Code で h2 部分のみ Embed
